## 0. Method notes / corrections to the brief

The brief stated that `META-INF/*.version` files carry a "6-byte little-endian int". **That is not the case in this artifact.** All 143 `.version` files are **plain-text UTF-8 version strings** terminated by `\n` (e.g. `1.9.3\n`, 6 bytes; `1.0.0-beta01\n`, 13 bytes; `2.55\n`, 5 bytes). They are emitted by AGP's `writeVersionFile` task, one file per resolved AAR/JAR, named `<group>_<artifact>.version` where the group uses `.` separators and the artifact uses `-`. The file name therefore encodes the *Maven* coordinate directly.

One exception: `META-INF/androidx.arch.core_core-runtime.version` contains a **Gradle task expression**, not a version:
`task ':arch:core:core-runtime:writeVersionFile' property 'version'` (67 bytes). This is a known AGP artifact for the `androidx.arch.core:core-runtime` module and is not a coordinate.

Class-presence cross-check was done by parsing the DEX header/string_ids/type_ids/class_defs directly (72,470 `class_defs` across 7 DEX files; 223,388 distinct strings; 74,287 distinct class-descriptor strings) — no `dexdump`/`baksmali` needed. Because R8 is in **full mode**, the majority of third-party classes are renamed into one- and two-letter packages (45,669 of 72,470 class_defs sit under obfuscated roots), so *package-name absence does not imply the library is absent*. Presence is therefore cross-checked against `assets/sentry-external-modules.txt` (the build's own resolved dependency list, 471 coordinates) and against raw string hits in the DEX.

## 11. Limitations

1. **R8 full mode** removed the package identity of 45,669 of 72,470 class_defs (63 %). "Not present in DEX" therefore means "no *named* classes", not "not in the build". The `sentry-external-modules.txt` list is used as the dependency ground truth instead.
2. Licences in §3 are mostly **upstream knowledge, not artifact evidence** — only Apache-2.0/RxJava, Apache-2.0/Jakarta CDI and the 12 AndroidX `LICENSE.txt` files are literally in the APK.
3. `assets/sentry-external-modules.txt` is generated by the Sentry Gradle plugin and reflects the **resolved** graph; a few entries may be build-time-only (e.g. `androidx.databinding:viewbinding`, `com.google.dagger:dagger-lint-aar`) and were never packaged.
4. The single build timestamp (2026-03-23 20:16:14 GMT) comes from the Sentry plugin, not from a reproducible build stamp.
5. `librive-android.so` embeds `10.1.0`; the Android wrapper version is `11.0.0` per the dependency list. These are different version axes (Rive C++ runtime vs. Rive Android SDK) — do not conflate.
6. The `apk` is the base of an XAPK; `config.en.apk`, `config.mdpi.apk` and `config.armeabi_v7a.apk` splits contain no DEX and no additional metadata.
